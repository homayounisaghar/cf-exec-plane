# PCG r138: repair the Telegram-to-Soniox source acquisition boundary

Canonical owner-controlled source: `homayounisaghar/capability-fabric` branch `work/pcg-telegram-asr-acquisition-r138-20261026`, commit `3c1eef1aa8abe4afcd81be71e27795e1c799b4c9`.

One owner Dexa mission failed on `audio_transcribe` (5 Telegram voices), `CATALOG_UPSTREAM_TOOL_ERROR`, upstream actual `WEB_PROVIDER_EVALUATE_TIMEOUT` at the 30-second WebK evaluation deadline. Separate read-only probes verified `communication.message.fetch` in about 1.9 s and ordinary `telegram_attachment_get` for the same voice in about 1.5 s, while a single direct ASR audio-source probe repeated the 30-second timeout. The r138 patch reuses the already provider-state-reconciled ordinary Telegram download to write private ASR material for audio <=32MiB, retaining existing large streaming fallback only above that bound. Telegram source acquisition is limited to two concurrent WebK browser workers; Soniox receives ONE shared 1..20-file batch afterward. Existing 7s/3s/DP merge and websocket cap are unchanged. The audio and transcripts are not in this public source. Only `pcg_web` is redeployed; unrelated ASR and Telegram container IDs are preserved. Automatic rollback to live r137 if health verification fails. Follow-up smoke must run an independent 1- and 5-voice probe, without replaying the in-doubt Dexa mission.
