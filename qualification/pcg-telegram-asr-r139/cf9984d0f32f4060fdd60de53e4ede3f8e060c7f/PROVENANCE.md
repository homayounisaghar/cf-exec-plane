# PCG r139: vetted Telegram ASR acquisition bridge with container-copy contract

Owner source: `homayounisaghar/capability-fabric` branch `work/pcg-telegram-asr-acquisition-r139-20261026`, commit `cf9984d0f32f4060fdd60de53e4ede3f8e060c7f`. The earlier r138 candidate failed PCG web health because its new module was not named `pcg_web_*.mjs` and thus was not copied by the existing web startup command. It was rolled back to r137 without promotion. r139 corrects the module filename/import and verifies all relative imports survive the container copy glob before deployment. A single voice ASR under old r137 failed reproducibly after 30s with `WEB_PROVIDER_EVALUATE_TIMEOUT`; fetching its Telegram message and downloading its original attachment separately succeeded in ~2s each. This fix reuses the provider-state-verified ordinary attachment download for audio up to 32MiB, retains existing larger-file streaming fallback, and bounds Telegram browser input acquisition to two workers before starting one simultaneous 1..20-file Soniox batch. Fixed 7s step/3s overlap, 514 global WS, and classic word DP merge remain unchanged. Only `pcg_web` restarts; automatic rollback to r137 on health failure. Public release contains no private audio/transcript/credentials. CI rehearsal reconstructed immutable r136->r137->r139 source and passed all 13 focused Soniox/source tests. After activation, test independent 1-/5-voice batches without replaying the in-doubt Dexa mission.
